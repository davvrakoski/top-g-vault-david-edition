# Error Reporting API - Grouping Rules as Code and New-Error Checks

The Error Report dashboard ([[Error Report]]) is great for humans. The **Error Reporting API** ([[Error reporting]]) lets you treat two things as code: your **grouping/ignore rules**, and a **"did this release add new errors?"** check.

## Key facts (official guide)
- Scopes: `universe.analytics:read` (details, list rules) and `universe.analytics:write` (create, update, reorder, ignore, delete rules). The key owner also needs analytics access, otherwise `403`.
- Every endpoint: 60 requests per minute per key.
- Rules: a .NET regex matched against the **message, not the stack trace**, with `Group` (count under an `output` label) or `Ignore` (moved into the shared "Other" bucket; totals unchanged). First match wins; changes take a few minutes; they don't rewrite errors already recorded.
- Limits: 100 creator rules per experience, no duplicate patterns. Patterns that start with an unanchored wildcard (`.*`), nest repeating quantifiers, or (for Ignore) lack 3 literal leading characters are rejected with `400`.
- Error details: `GET /universe-performance-raqi/v1/events/logging/universe/{universeId}/log-details?messageHashIds=...` with optional `startTime`, `endTime`, `keyword`, `placeId`, `placeVersions`, `firstSeenPlaceVersion`. Message hashes come from the Analytics API (`ErrorCount` broken down by `MessageHash`).

## 1. Rules as code (original)
Keep `ops/error-rules.json` in the repo, reviewed like any other change:

```json
[
  { "pattern": "^Player \\w+ not found$", "output": "Player <name> not found", "regexOperation": "Group" },
  { "pattern": "^Inventory: slot \\d+ out of range", "output": "Inventory slot out of range", "regexOperation": "Group" },
  { "pattern": "^AdService: request timed out", "regexOperation": "Ignore" }
]
```

A sync script creates any rule that is missing (it never deletes, so a typo can't wipe your rules):

```python
#!/usr/bin/env python3
"""Sync ops/error-rules.json -> Error Reporting rules. Env: ROBLOX_ANALYTICS_KEY, UNIVERSE_ID"""
import json, os, sys, urllib.request

BASE = "https://apis.roblox.com/log-attribute-http-service/v1/universe-regexes"
KEY = os.environ["ROBLOX_ANALYTICS_KEY"]
UNIVERSE = int(os.environ["UNIVERSE_ID"])
DRY_RUN = "--apply" not in sys.argv


def request(method, url, body=None):
    req = urllib.request.Request(url, method=method,
                                 data=None if body is None else json.dumps(body).encode())
    req.add_header("x-api-key", KEY)
    req.add_header("Content-Type", "application/json")
    with urllib.request.urlopen(req, timeout=30) as resp:
        raw = resp.read()
        return json.loads(raw) if raw else {}


existing = request("GET", f"{BASE}?universeId={UNIVERSE}&status=CreatorCreated")
have = {r["pattern"] for r in existing.get("universeRegexes", [])}

with open("ops/error-rules.json", encoding="utf-8") as f:
    wanted = json.load(f)

for rule in wanted:
    if rule["pattern"] in have:
        continue
    print(("WOULD CREATE " if DRY_RUN else "CREATE ") + rule["pattern"])
    if not DRY_RUN:
        request("POST", BASE, {"universeId": UNIVERSE, **rule})

print("dry run; pass --apply to write" if DRY_RUN else "done")
```

Run it with `--apply` only from a reviewed merge, using a key that has analytics write on that one experience.

## 2. New-error check after a release
1. In the dashboard, set **Place** and **New errors since** to the version you just published: this is the fastest human check in the first hour.
2. For automation: query error counts by message hash from the Analytics API for the last hour, then call log-details with `placeId` and `firstSeenPlaceVersion=<new version>`. Anything returned **first appeared in this release**.
3. Post the top few messages and counts to your team channel from CI, and link the tag-to-version mapping ([[Build Versioning - Git Tags, PlaceVersion and an In-Game Build Label]]).

## Good grouping habits
- Group errors that differ only by names, IDs or numbers, so one bug is one row.
- Ignore only proven engine noise or third-party spam, never your own errors "for now".
- Review Roblox's `AutoGenerated` suggestions weekly; dismiss bad ones (`.../{id}/ignore`) so they stop appearing.
