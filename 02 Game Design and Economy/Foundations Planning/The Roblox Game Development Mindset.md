# THE ROBLOX GAME DEVELOPMENT MINDSET

=================================================

The fastest way to ruin a project is to build 30 unfinished systems at once.

Use this loop:
PLAN -> PROTOTYPE -> TEST -> PROFILE -> FIX -> POLISH -> DOCUMENT -> REPEAT

Every feature should answer:
- What player problem does this solve?
- What does the player see?
- What does the server need to know?
- What can stay client-only?
- What happens if the player has 150ms ping?
- What happens on a phone?
- What happens with 20 players?
- What happens if an exploiter fires the remote manually?
- What happens if the asset fails to load?
- What is the fallback?
- How will I measure whether this feature improved the game?

QUALITY PYRAMID
1. It works.
2. It is secure.
3. It performs.
4. It feels responsive.
5. It is readable.
6. It is polished.
7. It is memorable.

Do not reverse this. A beautiful broken game is still broken.
