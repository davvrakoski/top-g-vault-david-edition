# One Material per MeshPart - Splitting vs Atlasing Multi-Material Models

In Blender a single object can carry five material slots: wood, metal, glass, rope, paint. Roblox's texture specification is blunt: "Mesh objects can only have one material assigned." A `MeshPart` takes one `TextureID` or one `SurfaceAppearance` and one Studio `Material`. Models bought online or generated by AI almost always arrive multi-material, so every Roblox artist needs a plan: **split** into several MeshParts, or **bake/atlas** everything into one texture set.

## Option 1: split by material

1. In Blender, Edit Mode > select all > **P > By Material**. Each material becomes its own object.
2. Name objects clearly (`Lantern_Metal`, `Lantern_Glass`).
3. Export one FBX with all of them. In the Studio Importer, untick **Import Only As Model** if you want separate assets, or keep the default (one Model asset containing several MeshParts).
4. In Studio, give each MeshPart its material: built-in `Material` (Glass, Metal) or its own `SurfaceAppearance`.

Good when: parts need different **Studio materials** (real Glass transparency, Neon glow, Metal reflections), or different physics, or must move separately (a door, a wheel).

Cost: one draw call per part-material, more instances, and pieces can misalign if pivots are inconsistent.

## Option 2: bake to one atlas

1. Duplicate the model, make one new UV map for the whole object (Smart UV Project or a careful manual unwrap, packed into 0-1).
2. Create one image per map (Color, Normal, Roughness, Metalness), e.g. 1024 px.
3. With Cycles, bake each original material's channel onto the new UVs (Bake type *Diffuse* with only *Color* contribution for albedo; *Roughness*; *Normal*; for metalness, temporarily route metalness into emission and bake *Emit*, a common workaround).
4. Replace all slots with one material using the baked images; export one mesh.

Good when: the object is static and repeated (props, furniture), or you want the fewest draw calls.

Cost: baking time, one shared texel density for everything, and no per-piece Studio materials.

Texture streaming caveat: the Textures and decals docs advise favouring unique textures over **shared** atlases unless the atlas sits on batchable parts, because when one object needs the atlas at high resolution the whole atlas streams in at that resolution. Atlasing one prop's own materials into its own texture set is fine; a giant atlas shared by unrelated props is the case to avoid.

## Option 3: hybrid

Atlas the opaque bulk into one MeshPart and split only the pieces that need a special Studio material: glass panes (Glass or transparency), glowing bits (Neon or an emissive mask), moving parts. A lantern becomes two parts, not five.

## Checking imports

- Several materials on one exported mesh: the Importer may produce separate pieces or show only one texture; treat a "texture not showing" import as a sign to split or bake (forum reports agree; exact importer behaviour varies by version, so check the preview tree).
- Material **colours** set in Blender (no image) do not become Roblox textures. Bake them, use vertex colours, or set `BasePart.Color` per split piece.

## Decision table

| Asset | Recommended |
| --- | --- |
| Static prop, many copies | Atlas (one MeshPart) |
| Vehicle with glass and lights | Hybrid: body atlas + glass part + light part |
| Weapon with moving magazine | Split moving parts; atlas the rest |
| AI-generated model with 12 slots | Bake to one atlas, then clean |
| Architecture kit | Trim sheet shared across pieces |
