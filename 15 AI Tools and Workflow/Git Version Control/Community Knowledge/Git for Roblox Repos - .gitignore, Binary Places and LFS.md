# Git for Roblox Repos - .gitignore, Binary Places and LFS

Roblox projects mix two very different kinds of data: **text** (Luau scripts, JSON/TOML config, project files) that Git handles perfectly, and **binary** blobs (`.rbxl` places, `.rbxm` models, meshes, textures, audio) that Git can store but cannot diff or merge. Repos that commit place files on every save balloon to gigabytes and produce unresolvable conflicts. The fix is a clear rule about what lives in Git, a good `.gitignore`, and Git LFS for the few binaries you must version.

## What belongs in the repo

| Commit | Don't commit (or use LFS) |
| --- | --- |
| `src/**/*.luau` scripts | `*.rbxl` / `*.rbxlx` working places (Studio + Team Create are the source of truth for the world) |
| `default.project.json`, `*.project.json` | `sourcemap.json` (generated by `rojo sourcemap`) |
| `wally.toml`, `wally.lock` | `Packages/`, `ServerPackages/`, `DevPackages/` (re-installed by `wally install`) |
| `rokit.toml` / `aftman.toml` / `foreman.toml` | build outputs (`build/`, `*.rbxl` produced by `rojo build`) |
| `selene.toml`, `stylua.toml`, `.luaurc` | `.vscode/` personal settings (commit a shared `extensions.json` only) |
| small `.rbxm` model files that are part of the build | OS junk: `Thumbs.db`, `.DS_Store` |
| docs, ADRs, test files | secrets: `.env`, Open Cloud API keys, cookies |

Roblox's own coding-harness starter repository follows the same idea: its `.gitignore` already excludes `.rbxlx`, because the place is saved to Roblox while scripts sync to files through Script Sync. The luau-lsp README likewise recommends ignoring `sourcemap.json`.

## Starter .gitignore (own)

```gitignore
# Roblox working copies and build outputs
*.rbxl
*.rbxlx
*.rbxl.lock
*.rbxlx.lock
build/

# Generated
sourcemap.json
Packages/
ServerPackages/
DevPackages/

# Tooling / OS
.vscode/*
!.vscode/extensions.json
.DS_Store
Thumbs.db

# Secrets
.env
*.key
```

If you **do** keep a canonical place file (for example a lobby template rebuilt by CI), name it explicitly and un-ignore it with a `!path/to/Lobby.rbxl` line, ideally tracked by LFS.

## Binary assets and Git LFS

Git LFS (Large File Storage) replaces large files in Git history with small pointer files and stores the content on an LFS server. Use it for binaries you genuinely need to version: source `.blend` files, `.fbx` exports, texture PSDs, canonical `.rbxm` models.

```bash
git lfs install
git lfs track "*.blend" "*.fbx" "*.psd" "*.rbxm"
git add .gitattributes
```

Limits to know: GitHub blocks pushing files over **100 MiB** without LFS and warns above 50 MiB; LFS storage and bandwidth on hosted Git services have quotas (check your plan). Roblox places themselves are limited to 100 MB on Roblox's side ([[Test Places, Staging Universes and Places in a Universe]]).

## Merge conflicts you can and cannot fix

- `.luau` and `.json`: normal text merges.
- `wally.lock`: regenerate with `wally install` after resolving `wally.toml`.
- `.rbxm` / `.rbxl`: **no merge**. Pick one side. Avoid by assigning one owner per binary asset, or convert models to Rojo `.model.json` / folders of scripts where practical.
- Optional: `git lfs lock` gives exclusive locks on LFS files so two artists don't edit the same `.blend`.

## Line endings and Windows
Add a `.gitattributes` with `* text=auto` and `*.luau text eol=lf` so StyLua and CI agree across Windows and macOS machines; otherwise formatting checks fail on every Windows commit ([[StyLua for Roblox - Config, Ignore Rules and CI Check]]).

## Checklist
- [ ] `.gitignore` excludes places, packages, sourcemap, secrets.
- [ ] `.gitattributes` sets LF for Luau and LFS for binaries.
- [ ] One owner per binary asset; LFS locking if several artists.
- [ ] `git status` is clean after `wally install` and `rojo sourcemap` (proves generated files are ignored).
